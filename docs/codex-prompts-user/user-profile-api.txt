현재 작업 브랜치는 feat/39-user-profile-api 이다.
이 작업은 feat/39-auth-interceptor 이 반영된 상태를 기준으로 한다.

기존 bread / breadrecord / user / auth 구현, AGENTS.md, docs/user-part-spec.md를 먼저 읽고 같은 스타일로 최소 수정 방식으로 이어서 작업해라.

[작업 전 필수]
1. UserService, UserMapper, UserMeResponse, UserStatsResponse를 먼저 읽고 요약해라.
2. 인증 인터셉터에서 request attribute로 어떤 값을 넣고 있는지 먼저 확인해라.
3. 기존 controller / swagger 스타일을 먼저 확인해라.
4. ApiResponse 응답 래퍼와 snake_case 직렬화 기대를 먼저 확인해라.

[이번 브랜치 목표]
현재 로그인한 사용자의 프로필 조회 API를 구현한다.

[이번 브랜치에서 구현할 범위]
- UserController 구현
- GET /users/me 구현
- request attribute에 저장된 userId 기준으로 UserService 호출
- ApiResponse<UserMeResponse> 구조로 응답
- 필요한 Swagger 설명 추가
- 기존 임시 X-USER-ID 기반 조회가 남아 있으면 자연스럽게 정리

[구현 원칙]
- 이제 /users/me 는 X-USER-ID가 아니라 인증된 access token 기준으로 동작해야 한다.
- 응답 DTO 필드명은 기존 직렬화 기대를 깨지 않게 유지해라.
- 컨트롤러는 얇게 두고 서비스 재사용을 우선해라.
- 새로운 예외 구조를 과하게 만들지 마라.

[출력 형식]
1. 참고한 기존 파일 / 패키지 요약
2. 생성 / 수정한 파일 목록
3. 파일별 핵심 변경 요약
   - 어떤 파일을 왜 바꿨는지 1~3줄씩 간략하게
4. /users/me 요청 흐름 설명
5. 다음 브랜치(test)에서 참고할 포인트

작업 종료 전에 반드시 아래를 출력해라.
1. 이번 브랜치에서 생성한 파일
2. 이번 브랜치에서 수정한 파일
3. 각 파일별 핵심 변경점 한 줄 요약
4. 다음 브랜치 작업자가 먼저 읽어야 할 파일 목록
5. 다음 브랜치에서 이어서 해야 할 핵심 TODO
