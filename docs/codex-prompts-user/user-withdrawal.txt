현재 작업 브랜치는 feat/41-user-withdrawal 이다.
이 작업은 feat/40-user-profile-test 가 반영된 상태를 기준으로 한다.

기존 bread / breadrecord / user / auth 구현, AGENTS.md, docs/user-part-spec.md를 먼저 읽고 같은 스타일로 최소 수정 방식으로 이어서 작업해라.

[중요 수정]
기존 Basic Auth + userKey/referrer 기준이 아니라, 이번 작업은 아래 정책으로 맞춘다.
웹훅 인증은 x-toss-webhook-secret 헤더 값을 서버의 TOSS_WEBHOOK_SECRET 과 비교하는 방식으로 간다.
웹훅 payload 는 eventType 기준으로 처리한다.
eventType 값은 UNLINK, WITHDRAWAL_TERMS, WITHDRAWAL_TOSS 이다.
앱 내부 직접 탈퇴는 서버가 토스 연결 끊기 API를 호출한 뒤, 콜백을 기다리지 않고 로컬 DB 사용자 데이터를 즉시 완전 삭제한다.

[작업 전 필수]
1. User 엔티티와 UserRepository 의 삭제 처리 방식을 먼저 확인해라.
2. UserSession / AuthService / logout 처리 구조를 먼저 읽고 요약해라.
3. 기존 프로젝트에서 soft delete 사용 패턴이 있는지 다시 확인하되, 이번 user 탈퇴에는 그대로 가져오지 말고 hard delete 기준으로 정리해라.
4. /users/me 와 인증 인터셉터 흐름을 먼저 확인해라.

[이번 브랜치 목표]
회원탈퇴 정책을 현재 Toss 연동 정책에 맞게 구현한다.
앱 내부 탈퇴는 hard delete 로 처리하고, 토스 웹훅은 eventType 에 따라 사용자 삭제 또는 토큰 초기화를 수행한다.

[이번 브랜치에서 구현할 범위]
- DELETE /users/me 구현
- 필요 시 AuthService 또는 UserService 에 회원탈퇴 메서드 추가
- 앱 내부 탈퇴 시 Toss 연결 끊기 호출 이후 로컬 사용자 데이터 hard delete
- 해당 user 의 모든 session revoke 또는 삭제 처리
- POST /auth/webhook/toss-unlink 구현
- x-toss-webhook-secret 헤더 검증
- eventType 기준 분기 처리
  - UNLINK: 토큰/세션만 정리
  - WITHDRAWAL_TERMS: 사용자 데이터 완전 삭제
  - WITHDRAWAL_TOSS: 사용자 데이터 완전 삭제
- 탈퇴 이후 /users/me 조회 불가 처리와 정책 정합성 확인
- 응답은 기존 ApiResponse 구조에 맞게 반환

[구현 원칙]
- user 탈퇴는 soft delete 하지 마라.
- 앱 내부 탈퇴는 로컬 사용자 row 를 삭제해라.
- 웹훅 UNLINK 는 사용자 row 를 유지하고 세션/토큰 정보만 정리해라.
- WITHDRAWAL_* 이벤트는 사용자 row 를 삭제해라.
- refresh token 원문을 저장 중이 아니면 세션 revoke / 삭제 방식으로 정리해라.
- 기존 예외 흐름과 한국어 메시지 톤을 유지해라.
- 필요 시 Swagger 문구를 최소 수정으로 반영해라.
