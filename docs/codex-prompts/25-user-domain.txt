현재 작업 브랜치는 feat/25-user-domain 이다.
기존 bread / breadrecord 구현과 AGENTS.md, docs/user-part-spec.md를 먼저 읽고 같은 스타일로 최소 수정 방식으로 이어서 작업해라.

[작업 전 필수]
1. 현재 저장소에서 bread, breadrecord 도메인의 entity / repository / dto 구조를 먼저 읽고 요약해라.
2. Auditing 필드와 엔티티 스타일을 먼저 확인해라.
3. ApiResponse 사용 방식도 먼저 확인해라.
4. 기존 코드에서 service / complexService 분리 패턴이 실제로 어떻게 쓰이는지 먼저 확인해라.

[이번 브랜치 목표]
user 도메인의 기본 구조를 추가한다.
아직 /users/me API를 완성하지 말고 뼈대만 만든다.

[이번 브랜치에서 구현할 범위]
- domain.user 패키지 추가
- User 엔티티 정의
- UserRepository 정의
- UserMeResponse 정의
- UserStatsResponse 정의
- 필요한 경우 mapper 또는 정적 팩토리 메서드 구조 준비
- 아직 controller, service의 실제 로직은 최소화

[구현 원칙]
- 현재 프로젝트에서 쓰는 entity 스타일을 최대한 맞춰라.
- lombok, jpa 어노테이션 스타일도 기존 엔티티와 통일해라.
- BaseEntity 같은 공통 엔티티가 이미 있으면 재사용하고 없으면 억지로 만들지 마라.
- 인증 관련 구조는 새로 만들지 마라.
- ApiResponse는 기존 것을 재사용하는 전제로 둔다.
- 한국어 톤 유지
- 없는 필드는 상상해서 과하게 넣지 말고 현재 프로젝트에 자연스럽게 맞는 최소 필드만 둬라.

[User 엔티티 필드 후보]
기존 프로젝트 스타일을 보고 자연스럽게 조정하되 아래를 우선 고려해라.
- id
- nickname
- email
- profileImageUrl
- bio
- createdAt
- updatedAt

1. 참고한 기존 파일 / 패키지 요약
2. 이번 브랜치에서 생성 / 수정할 파일 목록
3. 각 파일의 전체 코드
4. 다음 브랜치에서 이어서 구현할 포인트
