# Git / PR Rules

## 브랜치 규칙

- `main`, `develop`에 직접 작업하지 않는다.
- 기본 분기 기준은 `develop`
- PR target은 `develop`

## 커밋 규칙

- Conventional Commit 우선
- 한 작업은 가능한 한 한 커밋/작은 커밋 묶음으로 관리
- add 대상 파일을 명확히 분리해서 불필요한 변경이 섞이지 않게 한다

## 작업 보고 규칙

구현 응답 시 아래를 우선 정리한다:

1. 이번 작업에서 무엇을 했는지 짧게 요약
2. `git add` 해야 할 파일
3. 추천 커밋 메시지

필요하지 않으면 매번 PR 본문이나 이슈 문안까지 기본으로 길게 작성하지 않는다.

## PR / 이슈

- PR 제목, PR 본문, 이슈 제목/내용은 사용자가 요청했을 때 정리한다.
- 요청받으면 작업 요약, 검증 내용, 남은 리스크 기준으로 작성한다.
